# ADR 0002: 播放器封面（专辑封面）的来源、URL 策略与降级

- 状态：已确认
- 日期：2026-09-27
- 决策人：仓库所有者（Robotwizardt）

## 背景

笔记本屏里的网易云播放器原来只有「歌名 + 歌手·时长」和歌词，没有任何图片。
接口其实早就把封面发过来了：`/playlist/detail` 的 `tracks[].al.picUrl`
（实测 42/42 首都有），`src/data/netease.js` 的 `normalizeTrack` 也把它读成了
`picUrl`，只是界面从来没用。歌单本身还有一张 `playlist.coverImgUrl`。

麻烦点在 URL：接口返回的封面是 **http** 链接（如
`http://p4.music.126.net/lnOnBbP_H-052Hv5ls-QjA==/109951162964628408.jpg`），
一旦本作品集将来部署到 https 站点，这种链接会被浏览器当混合内容拦掉；
而且每张原图 100~200KB，42 首全列出来白白吃带宽。

## 决定

1. **来源**：只用接口给的 `al.picUrl`，不自建图片代理、不下载到本地。
   另外扩展 `getPlaylistTracks` 的返回值，多带一个歌单封面 `coverImgUrl`
   （之前只返回 `{ name, tracks }`），用于「还没选歌」时转盘中心的兜底图。
2. **URL 归一化**（统一在 `src/data/netease.js` 里做，界面只拿结果）：
   - 协议一律改成 `https`（实测 https 与原 http 同为 200 image/jpg）；
   - 加 CDN 缩放参数 `?param=WxH`：列表行内图用 `72y72`，转盘中心大图用 `256y256`
     （实测 `?param=120y120` 让单张从 3955B 降到 1968B）。两个档位写在
     `netease.js` 的 `ART_SIZE = { row, disc }` 里，界面调 `albumArtUrl(url, ART_SIZE.x)`，
     改尺寸不用碰 jsx。
   - `<img>` 上加 `loading="lazy"` 与 `referrerPolicy="no-referrer"`（CDN 不校验 referer）。
3. **降级**：图片加载失败、或**根本没有封面**（`picUrl` 为空串）时，都显示「灰底 + ♪」的
   **封面占位块**，尺寸与真封面一致，布局不跳动。注意这里不回退成歌单封面：
   歌单封面只在「还没选歌」时用。图片挂掉只影响图，不影响播放。
4. **呈现**（本 ADR 只记会影响后人的部分）：右侧大图做成 **黑胶转盘**
   （黑胶片 140px + 中心圆形封面 100px + 唱针，播放时旋转、暂停时静止），
   跟随当前播放曲目；点转盘 = 播放/暂停。列表每行左侧 36×36 圆角方图。
   面板尺寸仍是 700×400（不重算笔记本屏 3D 挂点）。
   动效具体值：转盘 **20 秒/圈**，唱针落下/抬起过渡 **300ms**。
   当前播放行：序号换成 **🔊**，整行淡白底（`rgba(255,255,255,0.10)`）。
5. **考虑过但没用的图种**：歌手头像（`ar.picUrl`）、网易云推荐 banner、歌词封面图。
   只用专辑封面是因为它逐曲唯一、与列表一一对应，其余图要么与曲目无关、要么尺寸不统一。

## 考虑过并否掉的替代

- **直接用原图直链**：省事，但带宽大、且 http 链接在 https 部署下会被拦。
- **加一层图片代理/镜像**：多一个要维护的服务，而网易云 CDN 本来就支持 https 与缩放。
- **把封面预先下载进仓库**：版权与体积问题，且歌单是接口动态返回的。

## 后果

- 换 CDN、换参数、加缓存，都只需改 `netease.js` 里的 URL 归一化，界面不用动。
- 「封面能不能显示」与「歌能不能播」彻底解耦：断网时封面退化成占位块，播放器其余部分照常。
